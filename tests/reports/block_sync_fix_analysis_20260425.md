# 区块同步问题分析与修复报告

**测试日期**：2026-04-25
**测试目标**：分析并修复Rust NRCS与Java NRCS的区块同步问题

## 发现的关键问题

### 1. 创世区块ID不匹配（已修复）

**问题**：数据库初始化时硬编码了创世区块ID为1，与Java NRCS的GENESIS_BLOCK_ID不匹配

**分析**：
- **Rust NRCS**：`GENESIS_BLOCK_ID = 3488276486778630462`
- **Java NRCS**：`GENESIS_BLOCK_ID = 3488276486778630462L`
- **数据库插入**：硬编码了 `block_id = 1`

**修复**：
- 修改 `crates/orm/src/genesis.rs`，使用 `GENESIS_BLOCK_ID` 作为创世区块的ID
- 调整SQL参数绑定，确保正确插入创世区块

### 2. 区块高度计算问题（已修复）

**问题**：Java NRCS的GetNextBlocks API返回的区块数据中不包含height字段，导致所有区块高度被设置为0

**分析**：
- Java Block.java的getJSONObject()方法不包含height字段
- Rust代码在缺少height字段时默认设置为0
- 导致数据库UNIQUE约束错误（多个区块高度为0）

**修复**：
- 根据区块在列表中的位置计算高度
- `base_height = start_idx as u32 + 1`
- 为每个区块设置正确的高度

### 3. 分批下载逻辑问题（已分析）

**问题**：Java NRCS每次最多返回36个区块，而Rust NRCS请求10个区块

**分析**：
- Java GetNextBlocks.java：`if (stringList.size() > 36) { return TOO_MANY_BLOCKS_REQUESTED; }`
- Java每次最多返回36个区块，即使请求更多
- Rust SEGMENT_SIZE = 10，每次请求10个区块

**结果**：
- Java返回36个区块（一个批次）
- Rust正确处理这些区块，按顺序分配高度
